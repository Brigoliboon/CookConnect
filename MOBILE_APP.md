# Mobile App Strategy

## Approach: Capacitor WebView

Wrap the existing Next.js PWA in a native shell using **Capacitor** (Ionic) — not a plain WebView. Capacitor provides native APIs and App Store–ready builds while keeping a single codebase.

## Why Capacitor over Plain WebView

| Feature | Plain WebView | Capacitor |
|---------|--------------|-----------|
| Splash screen | Manual | Built-in |
| Push notifications | Manual | Plugin |
| GPS background tracking | Manual | Plugin |
| File/camera access | Manual | Plugin |
| App Store deployment | Manual wrapper | `cap sync` + Xcode/Android Studio |
| Deep linking | Manual | Plugin |

## What Stays the Same

- All routes, auth, Mapbox, recharts — untouched
- Deploy updates instantly (no App Store review for web changes)

## Native Features We'd Use

| Feature | Plugin | Purpose |
|---------|--------|---------|
| Push notifications | `@capacitor/push-notifications` | Delivery alerts for customers/riders |
| Background geolocation | `@capacitor/geolocation` | Rider GPS tracking |
| Splash screen | `@capacitor/splash-screen` | Branded launch |
| Status bar | `@capacitor/status-bar` | Theme-matched header |

## Folder Structure

```
mobile/
├── android/          (generated by Capacitor)
├── ios/              (generated by Capacitor)
├── package.json
├── capacitor.config.ts
└── www/              (symlink to Next.js output)
```

The Next.js app lives at the root as-is. Capacitor reads the static build output.

## Setup

```bash
npm install @capacitor/core @capacitor/cli
npx cap init CookConnect com.cookconnect.app
npx cap add android
npx cap add ios
```

After each Next.js build:

```bash
next build && npx cap sync
```

## Build & Deploy

```bash
npx cap open android    # opens Android Studio
npx cap open ios        # opens Xcode
```

From there, generate a signed APK/AAB or IPA as usual.

## Trade-offs

- **Not truly native** — animations, navigation transitions feel slightly less native than SwiftUI/Jetpack Compose
- **Camera/file picker** requires a plugin bridge — cannot use `<input type="file">` reliably across all Android WebViews
- Still preferable to maintaining two separate native apps for this use case
